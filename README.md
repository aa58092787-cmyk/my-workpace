# 모아 — Supabase 저장형 칸반보드

## 빠른 설정
1. Supabase 프로젝트를 준비합니다. SQL Editor에서 `schema.sql` 전체를 한 번 실행합니다. 기존 `tasks` 테이블이 있으면 먼저 백업하고 충돌을 검토하세요. 자동 삭제·마이그레이션은 하지 않습니다.
2. 프로젝트의 API 연결 정보에서 프로젝트 URL과 publishable key(또는 legacy anon key)를 확인합니다.
3. `config.js`의 두 문자열을 바꿉니다. 공개 클라이언트 키만 사용하세요. **service_role / secret key 금지.**
4. Supabase Authentication에서 이메일 로그인을 활성화하고, URL 설정의 Site URL을 실제 Vercel 배포 도메인으로 지정합니다. 이메일 확인이 켜져 있다면 회원가입 → 확인 메일 클릭 → 앱으로 돌아와 비밀번호 로그인 순서입니다. 이 앱은 이메일 링크 자동 로그인이나 비밀번호 재설정 UI를 제공하지 않습니다.
5. 압축을 풀고 이 폴더의 파일들을 기존 Vercel 연결 저장소의 배포 루트에 반영합니다. 기존 원본은 별도로 백업하세요.
6. Vercel 프로젝트는 Framework Preset `Other`, Root Directory는 이 파일들이 있는 폴더, Build Command는 비워두고, Output Directory는 `.`로 설정합니다. 별도 Install Command와 의존성 설치는 필요 없습니다. 기존 프레임워크 설정이 남아 있으면 정적 배포 설정으로 변경하세요.
7. 저장소 변경을 배포한 뒤 회원가입·로그인합니다. 파일을 `file://`로 직접 열지 말고 Vercel HTTPS 주소로 접속하세요.

Vercel 프로젝트나 Supabase에 직접 접속해 변경한 결과물이 아니라, 해당 환경에 반영할 소스 패키지입니다. 실제 연결값은 포함되어 있지 않습니다.

## 데이터 저장 정책
- 카드 생성·편집·삭제·드래그 이동·백업 복원은 Supabase에 저장합니다.
- 로그인한 사용자만 자신의 카드에 접근합니다. 로그아웃하면 화면의 카드 목록도 지웁니다.
- 카드와 로그인 토큰 모두 브라우저 영구 저장소에 저장하지 않습니다. 새로고침하면 다시 로그인합니다.
- 다른 기기 변경은 30초마다 또는 포커스 복귀/새로고침 버튼으로 반영합니다.

## 기존 브라우저 카드 이전
1. 기존 원본 앱에서 `백업 저장`으로 JSON을 내려받습니다.
2. 새 앱에서 로그인하고 `불러오기`로 선택합니다.
3. 교체 확인 후 Supabase의 본인 카드만 교체됩니다. 기존 서버 카드가 있으면 먼저 백업하세요.

기존 앱에 남은 localStorage는 새 앱이 읽거나 지우지 않습니다. 새 저장 경로와 분리됩니다.

## 배포 후 확인
- 설정 전에는 설정 안내가 표시되고 카드를 생성할 수 없는가?
- 가입·이메일 확인·로그인이 되는가?
- 카드 생성, 수정, 상태 메뉴 이동, 드래그 이동, 삭제가 DB에 반영되는가?
- 재로그인 및 다른 기기에서 같은 계정의 카드가 조회되는가?
- 다른 계정에서는 첫 번째 계정의 카드가 보이지 않는가?
- Supabase API를 직접 호출해도 다른 계정의 카드를 읽거나 변경할 수 없는가?
- 검색, 우선순위, 통계, JSON 내보내기·불러오기가 동작하는가?
- 잘못된 백업은 거절되고 DB 제약 오류 시 기존 데이터가 롤백되는가?
- 네트워크 단절 시 성공 메시지 대신 오류가 표시되는가?
- 로그아웃 후 카드가 사라지고 새로고침하면 로그인이 필요한가?

## 문제 해결
- 연결 설정 오류: config.js 값과 https URL을 확인합니다.
- 권한/RLS 오류: schema.sql 실행 결과, 로그인 상태를 확인합니다. RLS를 끄는 방식으로 해결하지 마세요.
- 이메일 미인증: 확인 메일을 완료한 뒤 다시 비밀번호 로그인합니다. 메일 발송 제한이나 스팸함도 확인합니다.
- SDK 로드 실패: 브라우저가 esm.sh에 접근 가능한지 확인합니다.
- 저장 후 조회 실패: 저장 자체는 성공했을 수 있으므로 재시도 생성 전에 새로고침으로 서버 목록을 확인합니다.
